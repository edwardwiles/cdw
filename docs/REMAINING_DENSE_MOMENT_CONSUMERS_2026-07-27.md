## 0. Two things that turned out to matter more than the individual grep hits

1. **`select_G_from_H` itself is O(1), not a materialization.** It is defined in
   `cc_algo/PsiObjectiveBundle.jl:624` (`@view(H[:, 3:end])`) and
   `cc_algo/KLObjectiveBundle.jl:467` (`@view(H[:, 2:end])`) — a plain `@view` into `obj.H`'s
   already-allocated columns. Every one of the 49 repository-wide call sites of
   `CS.select_G_from_H(obj, obj.H)` costs nothing by itself; the real dense cost is in (a) the
   `obj.moments!(...)` call that WRITES into that view, or (b) whatever downstream code reads
   through the view (a `copy(...)`, a `BLAS.gemv!`, a `kkt_residual_blas` call). Do not read "N
   call sites of `select_G_from_H`" as "N dense materializations."

2. **The actual default per-Newton-iterate FG callback for `:dense_reference` is NOT in
   `full_aod_diag/d4_exact/` at all.** It is `cc_algo/PsiObjectiveBundle.jl`'s own callable method
   (`(obj::PsiObjectiveBundle)(x, g)`, restricted-family variant ~line 290-346), which does
   `BLAS.gemv!('N', 1.0, @view(H[:, 2:1+outer_constr_index]), -x, 0.0, arg0)` and matching
   transpose/constraint gemv!s **every KNITRO Newton iterate**, unconditionally, whenever a family's
   inner solve is dispatched via `inner_loop_internal_archgeneric` (`cm_hessian_architectures.jl:866`).
   This file predates the whole operator-FG port and has **zero** `no_dense_g_counters.jl`
   instrumentation. This matters concretely: **common-Fréchet's current production default
   (`CM_FRECHET_INNER_FG_BACKEND_DEFAULT[] = :dense_reference`) runs through exactly this path**,
   confirmed live in Part C (see companion doc) — a real, current, per-Newton-iterate dense-G
   dependency that none of the existing counters see, not because it doesn't happen but because
   nothing calls the recorder there.

## 2. Full-G-materialization vs. per-outer-point setup — the distinction the task asked to get right

The task brief itself flags: *"`full_G_materializations` may legitimately be always 0 if no code
path ever builds the complete dense matrix in one shot — confirm this is actually true via your
audit rather than assuming."*

It is **not quite true**, and being precise about why matters:

- In the strict sense the counter is clearly *meant* to test — a per-FG-callback (per Newton
  iterate), one-shot dense construction of the *entire* G matrix inside the hot inner-solve loop —
  **yes, this is confirmed 0 everywhere measured** (Part C). No operator/lookup FG callback ever
  builds a full dense G; each reads only the block(s) it needs, from compressed/operator sources.
- But `obj.moments!(@view(H[:,1]), select_G_from_H(obj,H), θ, obj.U, obj)` (row 2 of the table
  above) **does** build the complete `H` matrix (every economic + CM + ZC + Fréchet column) in one
  shot, **every single inner solve, for every family, always** — including families whose FG
  callback and Hessian never subsequently read most of those columns. This is not a bug: `H` is a
  genuinely shared, persistent, per-outer-point buffer that the Hessian's legitimate cross-term
  reads (row 8/9) and the post-solve verification recompute (row 6) both still depend on, and this
  session's own base commits (`f4c149e`/`1aeac63`) explicitly did NOT expand scope to remove that
  dependency ("Eliminating THAT dependency would be Hessian cross-block rework, explicitly out of
  scope" — `economic_operator.jl` header).
- If `full_G_materializations` were wired at this natural site, it would report `>0` (once per
  inner solve) for literally every family, every run — which would be a true but **misleading**
  signal if read as "the no-dense-G invariant is violated," since it is not part of the per-callback
  hot loop the invariant is actually about. This is exactly why this audit recommends **not** wiring
  it there (see companion doc §Part B) — the counter's only non-misleading natural home is a true
  per-FG-callback one-shot full build, which genuinely does not exist anywhere in this codebase, so
  `full_G_materializations=0` (unwired, no call site) is the historically-accurate signal, not an
  oversight.
