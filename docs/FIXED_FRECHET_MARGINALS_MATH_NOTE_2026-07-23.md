Branch: `experiment/fullA-fixed-frechet-marginals-2026-07-23`, forked from
`production/fullA-exact@d886d1d` (descends from tag
`cm-meanzc-production-ready-2026-07-23`).

## 1. What restriction is being added

Flexible common marginals (production default, `marginal_mode=:common_flexible`)
impose, for every non-reference origin `o` and grid point `l`,

```
E_F[ h_l(U_o) - h_l(U_ref) ] = 0
```

i.e. every origin's raw feature `h_l` matches the *reference origin's own*,
endogenously-determined level. This is "common but not fixed": the common
level itself is free (whatever the least-favorable `F` makes the reference
origin's own reweighted feature equal).

Fixed Fréchet marginals additionally pin that common level to the model's own
benchmark/calibration value, so that every origin (including the reference
origin) matches the SAME fixed target:

```
E_F[ h_l(U_o) ] = t_l*   for all o = 1..D, l = 1..L
```

## 2. Reduction to the codebase's native `U`-space (key simplification)

`precalc_common_marginals_cdf` (`common_marginals_moments.jl`) and every
downstream CM architecture (A/B/C) operate directly on `ctx.U`, the raw
`W x D` baseline-draw matrix — **not** on a separately materialized "Z"
Fréchet variate. `ctx.U` is generated by `genExpRands!` (`prepare_cc/genRands.jl`):

```julia
rand!(U); U[i] = -log(1 - U[i])
```

i.e. every column of `ctx.U` is **exactly** i.i.d. `Exp(1)` by construction —
not merely approximately, and not something that needs estimating. The
model's Fréchet variate `Z` (with `F*(z) = exp(-z^{-θ*})`, `θ* = 1/ctx.μHat`)
is obtained from `U` via a single fixed, origin-independent, strictly
monotonic transform `Z = g(U)` used inside the moment functions (the exact
sign of that transform is irrelevant to what follows).

Because `g` is the *same* deterministic bijection applied identically to
every origin's column, a restriction of the form "`U_o`'s marginal under `F`
equals a fixed reference law" is **exactly equivalent**, for every origin
simultaneously, to "`Z_o = g(U_o)`'s marginal under `F` equals the
corresponding pushed-forward reference law" — the two restrictions pick out
the identical set of feasible `F`'s. Concretely: since flexible CM already
builds its raw CDF feature as `1{U_o <= z_l}` with `z_l` an (empirical)
quantile of `U[:,ref]`, the *population* analogue of the same feature, in the
same `U`-parameterization, needs only:

- **analytic threshold**: `u_l* = F_Exp^{-1}(p_l) = -log(1 - p_l)` (exact,
  closed form — no estimation, no numerical root-finding), instead of the
  empirical `quantile(U[:,ref], p_l)`;
- **analytic target**: `t_l* = p_l` (trivial, since `u_l*` is by
  construction the `p_l`-quantile of `Exp(1)`).

This is a strict instance of "reuse exactly the same finite-grid feature
family and basis currently used for flexible common marginals" (task brief
§2) — no Z-space quantile function, no incomplete-gamma integral, and no
extra dependence on `θ*`/`σ` is needed for the CDF feature. `θ*`/`σ` are
still retrieved from the canonical context and stored/fingerprinted (§5,
§9), since they are part of what "the benchmark Fréchet marginal" means
economically and are required for the (currently dormant, see §4) cumulative
power block.

## 3. Reduction to "add one omitted common row" (task brief §3)

`precalc_common_marginals_cdf`'s existing block is, in the anchored
(pre-`R`-transform) basis, exactly the `(D-1)`-vector of **reference
differences** `d_o = h_l(U_o) - h_l(U_ref)`. This is a linear, invertible
reparameterization of the last `D-1` rows of the task brief's `D x D`
orthonormal matrix `Q` (whose rows 2..D span the "sum-zero across origins"
contrast space, same subspace `d` lives in after subtracting a constant).
`orthonormal_contrast_matrix(D)` is exactly the `(D-1)x(D-1)` change of basis
between the two representations; flexible CM's `:orthonormal` contrasts
column already IS `Q`'s rows 2..D acting on this same space — this is not a
new derivation, it is what `contrasts=:orthonormal` has always computed.

The row `Q`'s framework asks for is row 1, `D^{-1/2}(1,...,1)`, whose
population target is `sqrt(D) * t_l*`. Writing `(Qh)_1 = sqrt(D) e_ref +
D^{-1/2} sum(d)` and noting that under the *already-imposed* flexible-CM
restriction `d = 0` (in population, at the optimum), the row-1 target
collapses to `e_ref = t_l*` — i.e. exactly "pin the reference origin's own
raw feature to the target", which is the coordinate the anchored/reference-
differenced basis has always *omitted* (it only ever stores differences from
the reference, never the reference's own raw level). This is not a
coincidence introduced for convenience — it is an algebraic identity: adding
any single linear functional that recovers the omitted degree of freedom and
pins it to `t_l*`, together with the pre-existing `D-1` zero-contrast rows,
produces the *same* feasible set for `F` as literally building the `D`-row
`Q` and imposing `(Qh)_r = 0, r=2..D` plus `(Qh)_1 = sqrt(D) t_l*` — because
both constructions are full-rank reparameterizations of "every origin's raw
feature equals `t_l*`". The report's D=4 gate (§10.1, "transformed vs. naive
dense") verifies this numerically against the fully-naive per-origin
formulation, not merely asserts it algebraically.

**Concrete new column**, appended once per active grid point `l`:

```
g_common,l(s) = 1{U[s,ref] <= u_l*} - t_l*
```

This is a genuinely new column *type* relative to every existing CM column:
existing columns are paired differences of two *stochastic* per-draw
indicators (`h(U_o) - h(U_ref)`); the new column is a single stochastic
indicator minus a *constant*. That distinction is exactly why Architecture C
(§7 below) needs new, explicitly-derived assembly formulas rather than a
trivial re-use of the existing contingency-table code path — the existing
`build_bin_tables!`/`prefix_sum_tables!` precomputation is untouched and
fully reused (bin membership doesn't depend on any target), only the final
Hessian-block *assembly* step is extended.

## 4. Which feature families are actually active (not guessed)

`grep`-confirmed (§7 of the task brief's "do not guess" instruction):
`include_truncated_moment` (the eq.36 cumulative `(1-σ)`-power companion
block) defaults to `false` everywhere in the repository, is never set `true`
at any real call site, and `CMConfig` (`cm_config.jl`) has **no field that
can reach it** — `build_cm_production_context_v2` calls
`build_cm_augmented_obj`/`build_cm_production_context` without ever passing
it. **Only the plain CDF feature family (eq.35) is reachable from the
production `CMConfig` surface.** Consequently:

- The CDF feature family is fully implemented, wired into Architectures
  A/B/C, C+/Reference gradients, checkpointing, and gated at D=4/D=20.
- The cumulative-power target formula (§5 below) is implemented and unit-
  tested against independent numerical integration, for architectural
  completeness and to keep a future combination "not architecturally
  impossible" (task brief §4) — but it is **not wired into any reachable
  production code path**, exactly mirroring the block it would extend.
  This is stated explicitly, not silently assumed: if a future task
  activates `include_truncated_moment`, this same target machinery already
  has the formula ready, but the Hessian/Architecture-C wiring for that
  block does not exist yet and is out of scope here (the block itself is
  dormant upstream).

## 5. Benchmark target formulas

Let `p_l` be the grid probabilities already resolved by `CMConfig`
(`cm_resolve_probs_for_L`), `θ* = 1/ctx.μHat`, `σ = ctx.σ`.

**CDF feature** (active): `u_l* = -log(1-p_l)`, `t_l* = p_l`.

**Cumulative-power feature** (dormant, implemented for completeness): the
codebase's existing (inactive) eq.36 block computes, directly in `U`-space,
`U[:,ref]^pw * 1{U[:,ref] <= z_l}` with `pw = μHat*(1-σHat) = (1-σ)/θ*`. For
`U ~ Exp(1)`,

```
t_power_l* = E[U^pw 1{U <= u_l*}] = ∫_0^{u_l*} u^pw e^{-u} du = γ(pw+1, u_l*)
```

the lower incomplete gamma function (unnormalized), computed via
`SpecialFunctions.gamma_inc(pw+1, u_l*, 0)[1] * gamma(pw+1)` (regularized
`P` times `Γ(pw+1)`) — matches the task brief's `Y=Z^{-θ*}~Exp(1)`
parameterization exactly, since in this codebase `U` already plays the role
the brief calls `Y`, so no separate `a_l = -log(p_l)` re-derivation is
needed: `u_l* = -log(1-p_l)` is `Y`'s own `p_l`-quantile directly. Verified
against seeded Monte Carlo (`N=2×10^7`) to the sampling-error tolerance in
`test_frechet_reference_targets.jl`.

## 6. Inner dimension change

`ncm_flexible = (D-1)*L`. `ncm_frechet = D*L` (one extra column per grid
point). At `D=20, L=50`: `950 -> 1000` (+50 columns, +5.26%), all trailing
the existing `(D-1)*L` block (deterministic layout, §7 of the report).

## 7. Architecture C Hessian extension (derivation used by `hessian_cm_frechet_structured!`)

Let `A_l(s) = 1{bin(U[s,ref]) <= l}` (already available via the existing
`Ttab`/`Stab` contingency tables at `x=y=refIndex1`), `p_l` the constant
target, `w` the current inner weights, `M = obj.M`. Using
`CT[x,y,l,l'] = sum_s w_s 1{bin(U[s,x])<=l} 1{bin(U[s,y])<=l'}` (already
computed) and the identity `CT[ref,ref,l,l'] = sum_s w_s A_l(s) A_l'(s)`
(exact for any `l,l'`, not just the diagonal, since `T[ref,ref,k,h]=0` for
`k != h`):

```
H_E,common[j,l]        = (1/M)[ CS_[ref,j,l] - p_l * Wsum_E[j] ]
H_common,common[l,l']  = (1/M)[ CT[ref,ref,l,l'] - p_l'*CT[ref,ref,l,l] - p_l*CT[ref,ref,l',l'] + p_l*p_l'*M ]
H_common,contrast[l,(o,l')] = (1/M)[ CT[ref,o,l,l'] - CT[ref,ref,l,l'] - p_l*CT[o,o,l',l'] + p_l*CT[ref,ref,l',l'] ]
```

where `Wsum_E[j] = CS_[x,j,L] + Stab[x,j,L+1]` for any `x` (total weighted
sum of economic column `j`, independent of the partitioning origin). All
three formulas are expressed purely in terms of tables `build_bin_tables!`/
`prefix_sum_tables!` already produce — no new `O(W*...)` pass. Verified
against Architecture A's fully dense reference Hessian at D=4 (task brief
§10.1) to machine precision; this numerical check is the actual correctness
gate, not the algebra above by itself.
