# Fixed-dual vs. independently-reoptimized directional audit — 2026-07-23

Branch: `perf/fullA-cm-cplus-statecache-overnight-2026-07-22`. Answers Part I of the follow-up
brief: is the previously-observed opposite-sign phenomenon between the production fixed-dual
outer gradient and an independently reoptimized secant of `Delta_dual` a diagnostic artifact,
winner-boundary nonsmoothness, or a genuine gradient defect?

Harness: `full_aod_diag/d4_exact/directional_sign_audit.jl`. Raw data:
`results/cm_cplus_followup/directional_audit.csv` (per-coordinate bandwidth battery, 28 rows),
`results/cm_cplus_followup/directional_predictions.csv` (per-direction magnitude battery, 32
rows). Both generated by the run recorded in this doc; rerunning the harness reproduces them
(deterministic seeds `9013`/`90131`/`4242`).

## Verdict

**Diagnostic sign error in the test harness, not a genuine gradient problem.**

The example the brief quotes (`true_reoptimized = +2.282090e-02`, `fixed_dual = -2.021805e-02`)
traces to `full_aod_diag/d4_exact/overnight_cm_cplus_d4_gate.jl`, Section 4 (line 152 at the
commit the brief was written against):

```julia
true_secant = -(delta_dual_true(xfp) - delta_dual_true(xfm)) / (2h)   # <- extra leading minus
```

`delta_dual_true`/`Dp`/`Dm` are evaluated at exactly the same perturbed points
(`w0[k]±h`, mapped through `pivot_expand`/`exp` to `x_free`) that `Lp`/`Lm` (the fixed-dual
secant's own numerator) use. Per the algebra trace's own Section 6 derivation
(`docs/CM_GRADIENT_ALGEBRA_TRACE_2026-07-22.md`), `gfull[k] = (Lp - Lm)/(2h)` — no leading minus
— because `L_fix`'s sign is constructed to match `Delta_dual`'s sign exactly
(`lfix_from_q(q, ζ*) = -(mean(Ψ(q))+ζ*)`, the identical formula `Delta_dual` uses). The
ground-truth secant the test SHOULD have compared against is therefore
`(delta_dual_true(xfp) - delta_dual_true(xfm)) / (2h)`, matching `Lp,Lm`'s own numerator order.
The test as written negates this, which inverts the sign of the comparison at every coordinate
where the true derivative and the fixed-dual approximation actually agree (the normal case) —
producing exactly the "opposite sign, comparable magnitude" pattern the brief flagged.

This was not previously caught because Section 4's own `check(...)` only asserts
`secant_cp ≈ secant_ref` (C+ matches Reference — both fixed-dual, both correctly signed by
construction since neither touches `true_secant`); the mismatch against `true_secant` was printed
but never gated, and the printed mismatch was verbally attributed to "the known AUD-05
approximation" without checking whether the *sign* of that approximation gap should ever flip.

## I.1: sign-convention re-derivation, independently verified

Traced from source, not merely quoted from the algebra-trace doc:

1. **Scalar KNITRO sees**: `evalResult.c[1] = Δ = verify.Delta_dual` (`cm_checkpoint.jl`,
   `cb_F!`), where `Delta_dual = cbuf[1]/1e10` from an explicit `obj(inner_x, constr=cbuf)`
   recompute at the converged `(ζ*, λ*)` (`cm_production_bundle.jl:170-176`).
2. **`lfix_from_q` sign**: `lfix_from_q(q, ζ*) = -(mean(Ψ(q)) + ζ*)`, algebraically identical in
   form to `Delta_dual`'s own definition (`-(mean(Ψ(q*))+ζ*)`) — confirmed numerically at the
   base point with NO probe (`h=0`): `lfix_from_q(cache.q0, cache.ζstar)` vs `verify.Delta_dual`
   agree to `1.7e-17` (see harness output, "Sanity #1"). This is a stronger check than the
   algebra-trace doc performed — it verifies the two scalars are not merely the same *formula*
   but the same *value* at the anchor, which a formula-level argument alone cannot rule out (e.g.
   an index or constant-term error that happens to preserve algebraic form).
3. **`+h`/`-h` probe construction**: `wp[k] = w0[k]+h`, `wm[k] = w0[k]-h` in gravity-pivot
   `w`-space; `xfp/xfm` recovered via `pivot_expand` (direct linear assignment for non-pivot
   coordinates, no sign flip — confirmed by reading `pivot_expand`/`pivot_reduce`,
   `gravity_elimination.jl:60-68`) then `exp`. Both the fixed-dual secant (`Lp`/`Lm` via
   `lfix_incremental_at`) and the reoptimized secant (`Dp`/`Dm` via a fresh `archC_verified_state`
   solve) are evaluated at the IDENTICAL `xfp`/`xfm`.
4. **Numerator order**: fixed-dual is always `(value(+h) - value(-h))/(2h)`. The reoptimized
   ground truth must use the same order to be comparable — this is the one place the existing
   test diverged (see above).
5. **`evalResult.jac`**: assigned `gfull` directly, no negation (`cm_checkpoint.jl:328`,
   confirmed by direct read).
6. **Pivot/gravity-coordinate transforms**: `pivot_expand`/`pivot_reduce` are pure
   coordinate-selection/solve operations with no sign inversion for the free (non-pivot)
   coordinates (read directly, `gravity_elimination.jl`).

No analytic sign error exists in production code or in the algebra-trace doc's own derivation;
the error was confined to the follow-up test script's ground-truth construction.

## I.2: bandwidth-convergence and winner-stability battery

D=4 calibration point (`δ=1.0`, `contrasts=:orthonormal`), coordinates `k ∈ {2,3,5,16}` (spanning
early/mid/late A-block free indices), `h ∈ {1e-2, 5e-3, 2e-3, 1e-3, 5e-4, 2e-4, 1e-4}`. At every
`(k,h)`: `Dp/Dm` = reoptimized `Delta_dual` at `+h/-h` (fresh inner solve, `nStatus=0` at every
point — see `winner-boundary` note below for a caveat), `true_secant_asis`/`true_secant_corrected`
= the buggy/fixed reoptimized secant, `fixed_dual_ref`/`fixed_dual_cp` = Reference/C+ fixed-dual
secants, winner-switch counts at `+h` and `-h` relative to the base winner configuration.

**Results (28/28 rows)**:

- `sign(true_secant_asis) == sign(fixed_dual_ref)`: **0/28** (as expected — the bug flips every
  one).
- `sign(true_secant_corrected) == sign(fixed_dual_ref)`: **28/28**, at every `(k,h)` tested,
  including rows with up to 27 winner switches at `h=1e-2`. The sign never disagrees, even before
  winner-stability is reached — this is direct evidence against "genuine failure of the
  fixed-dual approximation at a smooth point" as well as against any residual sign concern.
- Winner-stability (`nswitch(+h)=nswitch(-h)=0`) is reached by `h=2e-3` to `h=1e-3` for all four
  coordinates, and holds down through `h=1e-4`.
- At the smallest winner-stable `h` for each coordinate, `true_secant_corrected` and
  `fixed_dual_ref` agree to 4-6 significant figures (`ratio ≈ 1.0000` at `k=2,3,5,16`; see
  "Per-coordinate convergence summary" in the harness output) — consistent with the known small
  finite-bandwidth/fixed-dual truncation term (AUD-05), not a defect.

**Classification, per coordinate**: `k=2,3,5,16` all classify as **diagnostic sign error** (the
harness bug) for the sign question, with a small residual **finite-bandwidth truncation error**
(AUD-05, expected, converging as `h→0`) fully accounting for the remaining magnitude gap. No
row classifies as "genuine failure of the fixed-dual approximation at a smooth point" or
"unresolved."

Caveat: `nStatus` at each `+h`/`-h` probe was checked only implicitly (via
`archC_verified_state`'s own `throw(CMExpectedSolveFailure(...))` on an unacceptable status —
no exception fired at any of the 56 probe solves in this battery, so every probe's `nStatus ∈
{0,-100,-101,-103}`, but the exact code was not individually logged per row). A follow-up wanting
the literal `nStatus` value at every probe (rather than "acceptable, unspecified-which" ) would
need a one-line harness change.

## I.3: directional predictions

Four normalized directions in `w`-space at the calibration point: the Reference fixed-dual
gradient direction itself (`dir_grad`), a single sparse coordinate (`e_3`, `dir_sparse` —
directly cross-checks I.2's `k=3` row), the top-3-magnitude-coordinate direction
(`dir_topmag`), and a random dense direction (`dir_switchheavy`, seed `4242`). `predicted_slope
= dot(g_ref_full, dir)` where `g_ref_full` is the actual production gradient
(`cm_production_gradient`, `h_mode=:fixed, h0=0.01` — production's own bandwidth choice, NOT a
converged small-h gradient) evaluated once at the base point. Symmetric secants
`(Delta_dual(w0+t·dir) - Delta_dual(w0-t·dir))/(2t)` computed via fresh reoptimization at
`t ∈ {2e-2, 1e-2, 5e-3, 2e-3, 1e-3, 5e-4, 2e-4, 1e-4}`.

**Results (32/32 rows)**:

- **Sign agreement is 32/32 at every direction and every magnitude tested**, including magnitudes
  with up to 60 winner switches (`dir_topmag` at `t=2e-2`) — the fixed-dual-predicted direction of
  movement is never wrong in this battery, even deep in nonsmooth territory.
- `dir_grad`: winner-stable by `t=1e-4`; `actual_secant/predicted_slope = 1.007` (0.7% error) —
  excellent quantitative agreement in the direction that actually matters for an outer solver (the
  gradient direction itself).
- `dir_sparse` (`= e_3`): winner-stable by `t=2e-4`; ratio `1.51` — a real ~50% quantitative gap
  at production's own `h0=0.01` bandwidth choice for this single coordinate in isolation (compare
  I.2's `k=3` row, which used a bandwidth matched to each probe `h` rather than a fixed `h0=0.01`
  and got much closer agreement — this is a bandwidth-choice effect, not a sign or magnitude
  defect in the underlying approximation itself).
- `dir_topmag`, `dir_switchheavy`: **no winner-stable magnitude found down to `t=1e-4`** — these
  directions are genuinely, persistently nonsmooth at every practically-probeable scale tested at
  this point. Classified as **winner-boundary nonsmoothness**, disclosed as a real property of
  the problem (many CM/economic decision boundaries are close together along generic combined
  directions at D=4/W tested here), not as a fixed-dual defect — sign agreement holds throughout
  even in this regime.

## Overall classification (per the brief's taxonomy)

| Coordinate/direction | Classification |
|---|---|
| All 28 I.2 rows (`k=2,3,5,16`, all `h`) | diagnostic sign error (harness bug) + finite-bandwidth truncation (expected, AUD-05) |
| `dir_grad`, `dir_sparse` (I.3) | diagnostic sign error (harness bug, same root cause) + bandwidth-choice-dependent truncation |
| `dir_topmag`, `dir_switchheavy` (I.3) | winner-boundary nonsmoothness (real, but sign-agreement holds regardless) |
| Any row | **NOT** genuine failure of the fixed-dual approximation at a smooth point |
| Any row | **NOT** unresolved |

**No blocker.** The persistent-opposite-sign observation that triggered this investigation does
not survive independent re-derivation: it was produced by an extra unary minus in one follow-up
test's own ground-truth construction, confirmed by (a) an analytic re-derivation from the
production call path with no assumption carried over from the prior report, (b) a
base-point-value sanity check the prior work did not perform, (c) a 28-row bandwidth/winner-
stability battery with 28/28 correct-sign results once the harness bug is fixed, and (d) a 32-row
independent directional battery (different code path, different construction, cross-checked
against (c) via the `e_3` direction) with 32/32 correct-sign results including deep into
winner-switch-heavy territory. Common-marginals-specific and unrestricted-path production code
were not modified to produce this result — only a diagnostic test script had the defect.
